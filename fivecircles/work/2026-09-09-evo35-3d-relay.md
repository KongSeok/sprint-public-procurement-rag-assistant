## 0. Why QLoRA is not the EH core

EvoHarness (EH) is the policy/runtime architecture: given bounded Belief/Progress/Experience state and the currently legal action schema, the Qwen3.5 policy emits the next strict action JSON, observes the tool result, then chooses again until termination. The learned object is therefore a multi-step next-action policy, not a standalone branch classifier.

QLoRA is only the parameter-efficient optimization mechanism proposed for SFT. It does not define EH and can be replaced by LoRA or another compatible adapter method without changing the action/state/tool contract.

"Branch learning" is useful shorthand only if it includes both choosing the next legal tool (`search`, `read`, `track`, `commit`, `recall`, `note`, `finish`, plus enabled visual tools) and generating that action's structured arguments. The policy is invoked again after every observation, so it learns multi-step trajectories rather than one static route choice.
