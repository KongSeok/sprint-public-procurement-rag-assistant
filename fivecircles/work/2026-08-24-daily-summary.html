MidProjectRAG 작업 요약

운영·보안·공통 프레임워크를 세우고, 실제 RAG 기준선을 만들기 직전까지 왔다. 지금은 “설계가 끝난 프로젝트”에서 “측정 가능한 제품”으로 넘어가는 경계다.

35%
전체 약 30~35% · 3주 일정 중 1주차 기반 작업 후반부
오늘

기반과 기준선 설계

  • 운영 정리: 새 프로젝트 기준, 문서 권위, 보안 원칙, 3주 배치 로드맵을 확정했다.
  • RAG 기준선: naive Dense RAG 우선, 평가에서 확인된 실패만 개선한다는 원칙과 4대 시나리오를 고정했다.
  • 데이터 프레임워크: CSV↔원문 100/100 조인과 HWP 96건·PDF 4건 전수 추출·무결성 검증을 완료했다.
  • 평가 프레임워크: API/GCP 공통 계약, dev/held-out 분리, 검색·인용·기권·지연·비용 지표를 구현했다.
내일

환경 마감과 Baseline 착수

  • 환경설정 마무리: HWP 파서 의존성과 재현 명령을 고정하고 표·페이지 fidelity를 표본 QA한다.
  • GitHub 운영 프로토콜: 브랜치·커밋·PR·교차 리뷰·머지·비공개 데이터 차단 규칙을 팀 기준으로 정리한다.
  • RAG 구현: 단순 청킹→임베딩→Dense top-k→근거 인용 답변·대화 문맥·안전 기권을 연결한다.
  • 성능 검증: 실제 corpus 기반 dev 문항부터 작성하고 retrieval·citation·latency·cost 기준선을 측정한다.
내일 이후

근거 기반 개선과 비교

  • 구조적 청킹→메타데이터 라우팅→top-k 순으로 한 요소씩 ablation한다.
  • MMR·reranking은 중복 또는 순위 문제가 실제 평가에서 확인될 때만 실험한다.
  • OpenAI API와 GCP L4 로컬 HF 스택을 같은 corpus·평가 계약으로 비교한다.
  • 마지막 주에 재현성, 안전검사, GitHub·보고서·발표 자료를 동결한다.

전체 프로젝트에서의 현재 위치

1. 운영·범위완료
2. 데이터·평가전수 추출 완료·gold 작성 대기
3. API Baseline다음 착수
4. 개선·GCP 비교평가 후 진행
5. 통합·제출마지막 주
Batch 0 운영·범위·보안·권위 체계 완료
Batch 1 실제 100/100 조인과 HWP 96건·PDF 4건 전수 추출 완료, fidelity 표본 QA만 남음
Batch 2 공통 평가 계약과 도구 완료, 실제 private 평가 문항 작성 대기
Batch 3 API naive Dense RAG 기준선 구현이 바로 다음 핵심 작업
Batch 4~6 근거 기반 검색 개선, GCP 비교, 통합 검증·제출 순으로 진행
