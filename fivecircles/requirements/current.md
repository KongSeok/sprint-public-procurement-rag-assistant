# MidProjectRAG Current Requirements

상태: Working baseline contract  
최종 갱신: 2026-08-24

## 1. 프로젝트 목표

`MidProjectRAG`는 실제 기업·정부 제안요청서(RFP) 100건을 대상으로,
사용자의 질문에 필요한 내용을 추출·요약하고 근거를 인용하는 사내 RAG 시스템이다.
OpenAI API 기반 스택과 GCP L4에서 실행하는 로컬 Hugging Face 스택을 모두 구현하고,
동일한 corpus snapshot과 평가셋으로 품질·지연시간·비용을 비교한다.

과제의 비즈니스 맥락은 공공입찰 컨설턴트가 수십 페이지의 RFP를 모두 읽지 않고도
주요 요구조건, 대상 기관, 예산, 제출 방식과 사업 목적을 빠르게 파악하도록 돕는 것이다.

## 2. 권위 자료

- 과제 범위와 제출 제약: 지정 Codeit Notion 가이드
- 실제 corpus: 사용자가 지정한 Google Drive 폴더의 `data_list.csv`와 원문 100건
- 충돌 처리: `fivecircles/agent/authority.md`의 단일 권위 순서를 따른다.
- 자료 상세와 실사 결과: `fivecircles/requirements/sources.md`

## 3. 사용자 시나리오

### FR-01 단일 문서 질의응답

사용자가 기관명·사업명 또는 문서 범위를 지정하면 해당 RFP의 요구사항, 목적,
예산, 일정, 제출 조건 등을 근거와 함께 답한다.

### FR-02 다중 문서 비교·종합

두 개 이상의 RFP를 공통 비교 축으로 정리하고, 각 사실이 어느 문서에 근거하는지 구분한다.

### FR-03 대화형 후속 질문

명시적으로 전달된 대화 history를 사용해 앞선 대상과 조건을 해소하고 후속 질문에 답한다.
평가와 재현을 위해 서버의 숨은 세션 상태에만 의존하지 않는다.

### FR-04 근거 부족 시 기권

corpus에 없거나 질문이 모호해 신뢰할 근거를 찾지 못하면 내용을 만들어내지 않고
기권 사유와 필요한 추가 정보를 반환한다.

## 4. 데이터 요구사항

- corpus는 총 100건이며 HWP 96건, PDF 4건이다.
- `data_list.csv`는 100행×12열이며 파일명 정규화 후 원문 100건과 1:1 대응한다.
- Drive 복사본의 `Copy of ` 접두사를 제거하고 Unicode NFC로 정규화해 조인한다.
- CSV의 `텍스트` 열은 잘린 미리보기이므로 최종 검색 본문으로 사용하지 않는다.
- 원문에서 본문·표·섹션 구조를 추출하고 문서/섹션/페이지 또는 문단 위치를 보존한다.
- 파싱 실패는 누락하지 않고 manifest의 상태와 경고로 기록한다.
- 결측·0원·1원 등 의심 금액은 임의 보정하지 않고 데이터 품질 플래그로 남긴다.
- 연락처·전화번호·이메일은 restricted 정보로 취급하고 로그와 공개 산출물에서 마스킹한다.

## 5. RAG 기능 요구사항

- 문서별 metadata를 이용한 범위 지정과 라우팅을 지원한다.
- 첫 기준선은 단순 청킹과 Dense top-k retrieval로 구현한다.
- 모든 사실 답변은 `doc_id`, `chunk_id`, 고정 `source_block_id`와 사람이 이해할 수 있는 위치를 인용한다.
- 생성 모델은 검색된 context만 근거로 사용하며 RFP 본문 속 지시문을 시스템 지시로 취급하지 않는다.
- 임베딩·생성 호출은 캐시할 수 있어야 하며 설정과 corpus hash를 실행 결과에 남긴다.
- MMR, hybrid search, multi-query, reranking은 기준선 평가에서 해당 실패 유형이 확인된 뒤에만 실험한다.

## 6. 실행 시나리오

### 시나리오 B — OpenAI API 기반

- 허용 모델: `gpt-5-mini`, `gpt-5-nano`, `text-embedding-3-small`
- 팀 총 API 사용 한도: USD 20
- 비용 원장과 hard stop을 둔다.
- 빠른 기준선을 위해 시나리오 B를 먼저 구현한다.

### 시나리오 A — GCP 로컬 실행

- 단일 VM: 4 vCPU, 16 GB RAM, NVIDIA L4 1장, 디스크 100 GB 이하
- 생성 모델과 임베딩 모델은 Hugging Face 계열에서 각각 1개를 선택한다.
- 광범위한 모델 벤치마크보다 공통 계약을 만족하는 재현 가능한 1개 스택을 우선한다.

## 7. 평가 요구사항

- 질문 유형: 단일 문서, 다중 문서 비교, 후속 질문, 미지 질문/기권
- 검색: Recall@k, MRR/nDCG, 다중문서 all-required-doc recall
- 생성: key-point coverage, 정확성, 근거 충실도
- 인용: validity, precision, factual-claim coverage
- 기권: precision/recall, false-answer rate
- 운영: error rate, p50/p95 latency, API token·비용, GPU 시간·VRAM
- dev와 held-out을 group 단위로 분리하고, held-out은 튜닝 완료 후 한 번만 실행한다.
- 두 스택은 동일한 corpus/eval/config hash와 질문 순서를 사용한다.

## 8. 보안과 공개 범위

- 원본 RFP는 비밀유지 대상이며 외부 공개·Git 업로드를 금지한다.
- 추출문, 원문 수준 청크, 벡터 DB, private gold span도 restricted로 취급한다.
- API key, SSH key, 서비스 계정 파일을 저장소·보고서·대화 로그에 남기지 않는다.
- 외부 전송 승인이 확인되기 전에는 corpus를 로컬에서만 처리한다. 승인 후에도 과정 제공 OpenAI/GCP 밖의 제3자 서비스에는 보내지 않는다.
- 공개 가능: 코드, 스키마, 집계 지표, 비식별화된 짧은 예시, 원문을 복원할 수 없는 파생 결과.
- 상세 제어는 `fivecircles/architecture/specs/security.md`를 따른다.

## 9. 협업과 일정

- 기간: 3주
- 팀원: 4명
- 역할을 완전히 고정하지 않되 배치마다 주 담당자 1명과 교차 검토자 1명을 지정한다.
- 진행·실패·의사결정을 매일 기록하며, 개인 협업 일지는 첫날부터 작성한다.
- 코드와 PDF 보고서는 D-1 19:00까지, 개인 협업 일지는 종료일 23:50까지 제출한다.

## 10. 범위 제외

- 프로덕션급 인증·다중 사용자·관리자 기능
- 대규모 배포·상시 모니터링
- 모델 파인튜닝과 광범위한 모델 탐색
- 제공된 100개 밖의 corpus 확장
- 모든 검색 고도화 기법의 무차별 구현
- 원본·청크·벡터 DB의 공개 배포

## 11. Definition of Done

1. HWP/PDF 100건의 추출 상태가 manifest에 모두 기록된다.
2. 동일 공통 계약으로 두 실행 스택을 호출할 수 있다.
3. 네 사용자 시나리오가 인용 또는 명시적 기권과 함께 동작한다.
4. 동일한 평가 snapshot으로 품질·지연시간·비용 비교표를 생성한다.
5. `--data-dir` 지정만으로 수집 이후 파이프라인을 재현할 수 있다.
6. 저장소 안전 검사에서 원문·비밀키·PII 유입이 0건이다.
7. 주요 선택과 기각 근거가 보고서·작업 로그에 남는다.

## 12. 현재 열린 결정

- HWP 표본 검증 후 주 추출기와 fallback을 Batch 1에서 확정한다.
- API/로컬 생성 모델의 최종 선택은 공통 평가 계약 이후 dev 결과로 확정한다.
- 절대 latency 합격선은 과제에 명시되지 않았으므로 기준선 측정 후 목표를 정한다.
