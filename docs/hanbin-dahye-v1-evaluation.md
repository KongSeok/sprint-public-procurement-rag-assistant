## 6. 문서 검색과 청크 검색의 차이

한빈님 당일 브리핑은 Mini131에서 문서 검색 지표 약 0.972와 청크·컨텍스트
지표 약 0.611 사이의 차이를 지적했다. 이번 B-v1에서도 별도 진단 결과 문서
Recall 0.922에 비해 Context Fact Coverage가 0.616으로 낮아 같은 현상이
재현됐다. 두 실험은 평가셋과 세부 조건이 완전히 같다고 확인된 비교는 아니므로
수치의 직접적인 우열보다 진단 방향을 본다.

| 진단 단계 | 결과 | 의미 |
| --- | ---: | --- |
| 정답 문서 검색 | 92.2% | 정답 문서 ID가 검색 결과에 포함됨 |
| 검색 Context의 필수 사실 포함 | 61.6% | 생성기에 전달된 문맥에 필요한 사실이 존재함 |
| 생성 답변의 필수 사실 포함 | 54.6% | 최종 답변이 필요한 사실을 표현함 |

따라서 높은 문서 Recall만으로 검색이 충분하다고 판단할 수 없다. 현재 가장 큰
손실은 정답 문서 내부의 적절한 청크를 선택하고 생성 컨텍스트로 구성하는
구간에서 발생한다. Context 61.6%에서 최종 답변 54.6%로 내려가는 약 7.0%p의
추가 손실은 생성·프롬프트·자동 채점 표현 차이를 함께 포함한다.

## 7. 다혜님 채점식과 잠정 종합점수

다혜님이 9월 8일 올린 `feat/generation-pipeline-prompt-eval` 브랜치의
`notebooks/generation_experiment_4_scoring.ipynb`에서 생성 답변용 종합 채점식을
확인했다. 관련 최신 커밋은 생성 함수 `647931b`, 프롬프트 `f028e5f`다.

채점 방식은 다음과 같다.

1. 일반 답변 문항은 필수 핵심 사실(`required_key_points`)이 답변에 포함된 비율을
   문항 점수로 사용한다.
2. 기권 문항은 지정된 기권 표현이 있으면 100점, 없으면 0점이다.
3. 채점 가능한 모든 문항 점수의 산술평균을 최종 점수로 사용한다.

다혜님 노트북은 Golden40의 `required_key_points`를 사용하지만, 이번 B-v1은
Golden Set v3의 `required_fact_groups`로 이미 평가했다. 따라서 동일 개념으로
변환해 일반 문항에는 `Fact Coverage × 100`, 기권 문항에는 기권 일치 시 100점,
불일치 시 0점을 적용한 **호환 잠정 점수**를 계산했다.

| 평가 구간 | 문항 수 | 호환 잠정 점수 |
| --- | ---: | ---: |
| 전체 | 79 | **55.77/100** |
| Answer | 56 | **59.82/100** |
| Set | 13 | **49.29/100** |
| Visual | 10 | **41.50/100** |

참고로 다혜님 노트북에 기록된 기존 Golden40 점수는 전체 89.58점이며,
Single-doc 96.67점, Multi-doc compare 75.00점, Follow-up 86.67점, Unknown
100.00점이다. 그러나 평가셋, 검색 Context, 정답 필드와 자동 매칭 구현이 다르므로
이 89.58점과 B-v1의 55.77점을 모델 우열처럼 직접 비교하면 안 된다.

이번에 찾은 산식은 **생성 답변의 정답성·기권을 합산하는 점수**다. Retrieval,
Context, Citation, Generation 지표를 가중합하는 전체 RAG 공식 종합 산식은 현재
확인되지 않았다. 따라서 55.77점은 검색과 생성의 최종 결과가 답변에 반영된
정도를 보여주는 잠정 점수이며, 검색 병목의 위치는 문서 Recall과 Context Fact
Coverage를 함께 보고 판단한다.

- Context에 필수 사실이 전부 있었던 사례: **0/15건**

따라서 이번 실행의 잘못된 기권은 주로 생성 모델이 답변을 회피해서가 아니라,
필요한 정보가 검색 Context에 들어오지 않아 발생한 것으로 판단한다.

주요 개선 대상은 다음과 같다.

1. 청크 검색: 문서 적중과 별개로 정답 근거가 있는 절·표를 찾는 지표를 개선해야 한다.
2. Set 질문: 문서별 1개 결과 제한, 후보 수 확대, 조건 필터 개선이 필요하다.
3. Visual 질문: 표 구조와 그림 설명을 보존하는 별도 파싱이 필요하다.
4. 생성: 충분한 Context가 들어온 사례만 분리해 프롬프트 성능을 평가해야 한다.
5. 인용: 답변에 사용한 모든 필요 문서를 마지막 근거 줄에 빠짐없이 기록해야 한다.

## 10. 해석 시 주의사항

- Fact Coverage는 `required_fact_groups`의 문자열·날짜 변형을 찾는 자동 진단
  지표다. 의미가 맞는 동의 표현을 놓치거나, 문자열만 같고 문맥이 틀린 답을
  통과시킬 수 있으므로 사람 또는 LLM Judge의 정답성 평가와 동일하지 않다.
- 기권 일치율은 다혜님 scoring notebook의 기권 표현 목록을 사용한 문구 기반
  판정이다. 일부만 답하고 나머지를 기권한 답변도 기권으로 잡힐 수 있다.
- Golden Set이 아직 draft이므로 팀 검수 후 점수는 달라질 수 있다.
- 다혜님 최신 노트북에서 생성 답변용 종합 채점식은 확인했다. 다만 B-v1과
  평가 데이터 구조가 달라 55.77점은 같은 원리를 적용한 잠정 호환 점수다.
- Retrieval, Context, Citation, Generation을 임의의 가중치로 합치는 전체 RAG
  공식 종합 산식은 확인되지 않았다. 서로 다른 진단 지표는 별도로 유지한다.
- 문서 Recall을 청크 검색 정확도 또는 답변 가능률로 해석하면 안 된다. 검색
  개선 판단에는 Context Fact Coverage를 반드시 함께 사용해야 한다.
