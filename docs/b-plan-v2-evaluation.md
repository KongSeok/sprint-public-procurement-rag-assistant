## 1. 실험 목적

B-v1과 같은 데이터·임베딩·검색 엔진·생성 모델을 유지하면서, 2026-09-08에
추가된 최신 생성 함수와 V9 프롬프트를 적용해 전체 성능 변화를 확인했다.

단, 최신 생성 함수에는 문서 힌트 추출, 질문 유형 분기, 조건 필터, Context 선택
규칙도 포함되어 있다. 따라서 이번 결과는 프롬프트만 바꾼 순수 생성 비교가
아니라 **Context 구성과 생성 로직을 함께 교체한 엔드투엔드 비교**다.

## 2. 적용 버전과 구성

| 구성 | 기준 |
| --- | --- |

최신 생성 함수의 문서 힌트·필터·질문 유형별 Context 구성과 프롬프트 본문은
그대로 적용했다. 통합 패키지에서 동작하도록 모듈 import 경로만 조정했다.

## 7. 인용 점수 0% 원인

B-v2 답변은 실제로 `근거: 파일명` 형태로 문서명을 자주 기록했다. 그러나 공통
평가기의 인용 계약은 답변 마지막 줄의 `[근거: doc_id1, doc_id2]` 형식만
인식한다. 대괄호가 없는 최신 출력은 전부 형식 실패로 처리되어 엄격한 Citation
Coverage가 0%가 됐다.

이는 근거 문서가 전혀 없었다는 뜻은 아니다. 별도로 답변 전체에서 정확한 정답
문서명을 검색한 결과 문서명 언급률은 78.63%였다. 다만 이 보조 지표는 문서명이
답변에 등장했는지만 확인하며, 실제 답변 생성에 사용했는지까지 보장하지 않는다.

따라서 다음 통합에서는 생성 답변의 마지막 줄을 `[근거: ...]` 계약으로 맞추거나,
평가기가 두 형식을 모두 정규화해서 읽도록 해야 한다. 이후 Citation Coverage를
다시 계산해야 B-v1과 공정하게 비교할 수 있다.

## 8. 결론

B-v2는 생성 오류 없이 79문항 전체를 완료했고, 호환 종합점수가 55.77점에서
63.88점으로 8.11점 상승했다. Context Fact Coverage와 답변 Fact Coverage도
각각 4.60%p, 8.34%p 개선되어 최신 Context 구성·프롬프트의 효과가 확인됐다.

반면 Retrieval Recall은 7.77%p 하락했다. 현재 버전을 바로 최종안으로 확정하기
보다는 다음 두 작업을 우선해야 한다.

1. `[근거: ...]` 출력 계약을 복원한 뒤 Citation Coverage를 재채점한다.
2. B-v1의 고정 검색 Context에 V9 프롬프트만 적용하는 통제 실험을 추가해,
   Context 라우팅 개선과 프롬프트 개선 효과를 분리한다.
