# VLM + v3.0.1 + 인용 형식 통일 실험

## 실험 개요

이번 실험은 최신 텍스트 생성 파이프라인에 기존 Qwen3-VL 시각 판독 결과를 연결하고, 채점기 v3.0.1과 통일된 인용 형식을 적용한 통합 평가다.

## 실험 구성

| 구분 | 내용 |
| --- | --- |
| 평가 문항 | Golden Set v3 79문항 |
| 원본 문서 | 98개 |
| 전체 청크 | 18,239개 |
| 검색 대상 청크 | 14,575개 |
| Parent 청크 | 3,664개 |
| 검색 방식 | KURE 벡터 검색 + BM25 |
| 벡터 DB | Chroma DB |
| 임베딩 모델 | `nlpai-lab/KURE-v1` |
| 임베딩 실행 장치 | CPU |
| 답변 생성 모델 | `gpt-5-mini` |
| 시각 판독 모델 | `Qwen/Qwen3-VL-8B-Instruct` |
| 생성 코드 기준 | `9c4429e` |

| 인용 형식 | `[근거: 문서명1, 문서명2]` |
| 실행 오류 | 0건 |

## 단계별 결과 비교

| 실험 | End-to-End | 어휘 사실 점수 | 비고 |
| --- | ---: | ---: | --- |
| 기존 채점기 v3.0.1 기준 | 70.12 | 74.24 | 이전 생성 결과 재채점 |
| 최신 생성 + 인용 통일 | 82.33 | 82.32 | 텍스트 중심 |

### 변화량

최신 텍스트 실험 대비:

- End-to-End: `82.33 → 85.37` (**+3.04%p**)
- 어휘 사실 점수: `82.32 → 87.63` (**+5.31%p**)

기존 v3.0.1 결과 대비:

- End-to-End: `70.12 → 85.37` (**+15.25%p**)
- 어휘 사실 점수: `74.24 → 87.63` (**+13.39%p**)

초기 채점기 v3.0.0의 74.67점은 과대 채점 문제가 확인된 값이므로 공식 비교에서 제외한다.

전체 관측 상승폭은 3.04%p였다. 그림 문항 외 일부 답변이 API 생성 변동으로 상승하거나 하락했기 때문이다.

## 인용 성능

| 인용 지표 | 결과 |
| --- | ---: |
| 형식 통과율 | **100%** |
| 인용 Recall | **91.77%** |
| 인용 Precision | **92.15%** |

모든 답변은 채점기가 인식하는 다음 형식을 준수했다.

```text
[근거: 문서명1, 문서명2]
```

인용 형식 문제는 해결됐지만 인용 내용이 모두 완벽한 것은 아니다.

- 인용 Recall 91.77%: 필요한 정답 문서 중 약 8.23%가 인용에서 누락
- 인용 Precision 92.15%: 인용한 문서 중 약 7.85%는 정답 문서가 아님

## 다중 문서 Set 성능

| 지표 | 결과 |
| --- | ---: |
| Macro Precision | 74.23% |
| Macro Recall | 95.00% |
| Macro F1 | 79.68% |
| 완전 일치율 | 46.15% |
| 정답 개수 일치율 | 61.54% |

Recall이 95%이므로 필요한 문서를 대부분 찾았다. 반면 Precision이 74.23%이므로 정답 문서 외 불필요한 문서를 함께 반환하는 문제가 남아 있다. 앞으로는 검색 범위를 넓히는 것보다 결과 목록에서 불필요한 문서를 제거하는 후처리가 중요하다.

VLM은 그림 문항에만 적용됐기 때문에 Set 성능은 텍스트 전용 실험과 동일하다.

## 0점 문항

텍스트 전용 실험에서는 0점 문항이 9건이었으나 VLM 통합 후 6건으로 감소했다.

| 문항 | 주요 원인 |
| --- | --- |
| `supplemental-qa-g03` | 복수 마감 정보를 모두 답하지 못함 |
| `supplemental-qa-g04` | 목표 문서 검색 실패 후 기권 |
| `supplemental-qa-g13` | 목표 문서 검색 실패 후 기권 |
| `supplemental-qa-g22` | 완전 기권 정답을 부분 답변으로 판정 |
| `supplemental-qa-g25` | 다른 사업을 찾아야 하지만 기준 사업 자체를 반환 |
| `visual-pdf-table-003` | 표 문항의 구조 및 항목 판독 실패 |

VLM이 적용된 그림 문항에는 0점 문항이 남아 있지 않다. 남은 시각 문항 0점 사례인 `visual-pdf-table-003`은 그림 VLM 경로가 아니라 구조화 텍스트로 처리한 표 문항이다.

## 검색과 생성 문제

### 검색 문제

- `g02`: 버스정보시스템 문서 대신 무관한 문서 검색
- `g04`, `g13`, `g21`, `g24`: `2025년 통합접수시스템 운영` 문서를 찾지 못함
- `c19`: 필요한 6개 문서 중 1개 누락
- `g25`: “다른 사업”을 찾아야 하는데 기준 사업 자체를 반환

### 생성 문제

- `g03`: 두 종류의 접수 마감을 각각 답하지 않고 하나로 합침
- `g08`: 필수 사실 일부 누락
- `g12`: 일부만 답하고 부분 기권
- `g19`: 필수 사실 일부 누락
- `h16`: 정답 요소 일부 누락
- `g22`: 완전 기권해야 하는데 부분 답변으로 판정
- `visual-pdf-table-001`: 표 답변 일부만 맞아 50점
- `visual-pdf-table-003`: 정답 문서는 찾았지만 표 내용을 답하지 못해 0점

## 결론

최신 생성 파이프라인에 Qwen3-VL 시각 근거, 채점기 v3.0.1, 통일된 인용 형식을 결합한 결과 전체 End-to-End 점수는 **85.37점**을 기록했다.

VLM이 적용된 그림 문항 4건은 모두 100점을 기록했고, 텍스트 전용 실험에서 실패했던 HWP 그림 2건과 PDF 그림 1건이 완전히 개선됐다. 정확한 대상 이미지가 주어진 경우 VLM 판독 결과를 생성 파이프라인에 연결하는 방식이 효과적임을 확인했다.

## 재현성 주의사항

- 이번 실행은 문항마다 VLM을 새로 호출한 것이 아니라 기존에 저장된 시각 판독 결과를 연결한 실험이다.
- 대상 이미지 선택에 Golden Set의 근거 참조값을 사용했으므로 완전한 블라인드 시각 검색 평가로 해석하지 않는다.
- 실행 당시 문서 ID 추출 정규식은 파일명 내부의 `]` 문자를 끝표시로 오인할 가능성이 있었다. 따라서 검색 Recall, Set 지표 및 이를 포함한 End-to-End 점수는 수정된 노트북으로 재실행해 확인할 필요가 있다.
