# 채점기 개선 보고서 v2 → v3.0.1

작성일: 2026-09-09

## 1. v2에서 고친 것

- **실행 오류와 기권 분리**: `answered`, `partial_answer`, `abstained`, `empty_response`, `execution_error`의 5가지 상태로 구분한다. API 오류는 더 이상 기권으로 잡히지 않는다.
- **점수 이원화**: 정상 생성분만 보는 `conditional_score`와 오류·빈 응답까지 포함하는 실제 시스템 관점의 `end_to_end_score`를 분리한다.
- **부분 답변 정상 분류**: “예산 3억, 계약기간은 확인 불가” 같은 답변을 전체 기권이 아닌 `partial_answer`로 분류한다.
- **지표명 정정**: `compatible_overall_score`를 `lexical_fact_score`로 변경했다. 이는 종합 성능이 아닌 어휘 호환성 보조지표다.
- **Set 정보 누출 제거**: Set 문항 채점 시 정답 개수로 검색 대상 수를 미리 정하던 방식을 제거했다.

## 2. v2의 잔여 문제와 v3.0.0의 개선 시도

- **기권 인식 누락**: “확인되지 않습니다” 같은 실제 기권 표현을 인식하지 못해 기권이 정답인 문항이 채점에서 빠지는 문제를 해결하기 위해 표현 목록을 확장했다.
- **조사·어미 차이**: “BIS와”와 “BIS”, “않음”과 “않습니다” 같은 차이를 완화하기 위해 Kiwi 형태소 분석기로 조사·어미를 제거한 뒤 비교하도록 수정했다.
- **숫자 표기 차이**: “100분의 10”과 “10%”, “20억”과 “20억원”을 제한적으로 동치 처리했다.

## 3. v3.0.0 부작용과 v3.0.1 재수정

형태소가 40% 이상 겹치면 통과시키는 v3.0.0 방식은 과대 채점을 발생시켰다.

- `c18`: 마감일을 답하지 않았지만 “입찰”, “제출” 단어만 겹쳐 0점에서 100점으로 상승
- `g23`: 페이지 숫자를 답하지 않았지만 “본문”, “페이지” 단어만 겹쳐 0점에서 100점으로 상승

따라서 v3.0.0의 74.67점은 공식 비교에서 제외하고 v3.0.1에서 다음과 같이 보수적으로 수정했다.

- 필수 문구에 숫자가 있으면 답변에도 그 숫자가 있어야 통과
- 형태소는 40%가 아닌 **100% 일치**해야 인정
- v2가 인정하던 표현은 유지
- v3의 추가 구제 범위는 조사·어미와 검증된 숫자 표기 차이로 제한

## 5. 실행별 사례 해석

### C19

C19는 실행 결과를 구분해서 해석해야 한다.

- 이전 v2 저장 답변은 평택시 BIS와 인천공항 ERP의 80:20 정보를 찾지 못하고 “확인되지 않습니다”라고 답해 66.67점을 받았다. 이 결과는 해당 실행의 검색·생성 문제다.
- 최신 VLM 통합 답변은 80:20 두 사업, 90:10 네 사업, 비율 차이의 구체적 이유 미기재를 모두 포함했다. 채점기 v3.0.1에서 필수 사실 3/3, 100점으로 정상 채점됐다.
- 조사·어미 차이로 실패했던 별도 사례는 v3.0.1의 Kiwi 기반 정규화 대상이다.

따라서 “C19는 항상 검색 실패” 또는 “항상 조사 매칭 실패”라고 일반화할 수 없다. 동일한 실행 ID와 답변, 채점기 버전을 기준으로 원인을 기록해야 한다.

### G22

이전 v2 저장 답변의 짧은 “확인되지 않습니다”는 v3.0.1에서 정상 기권으로 판정됐다. 그러나 최신 VLM 통합 답변은 확인 가능한 사업예산을 제시한 뒤 시장 평균 자료가 없어 비교할 수 없다고 기권했고, 채점기는 답변 안의 숫자를 근거로 `partial_answer`라고 판정했다.

모델은 질문의 최종 비교 판단을 내리지 않았으므로 최신 G22는 **근거 포함 기권을 채점기가 부분 답변으로 오분류한 사례**다. 기권 문구가 포함됐다는 이유만으로 무조건 정답 처리해서도 안 되지만, 확인 가능한 배경 사실을 설명했다는 이유만으로 기권을 오답 처리해서도 안 된다.

향후에는 `abstained_with_context` 같은 상태를 추가하거나, 기권 정답 문항에서 모델이 금지된 최종 판단을 실제로 내렸는지 별도로 검사하는 방식이 필요하다.

### Set B15

실행에 사용된 골든셋은 정답 문서를 12개로 보유하지만 원문 검수 결과는 15개다. 최신 모델은 15개를 모두 반환했으나 누락된 3개가 오답으로 처리됐다. 이는 채점기 계산식 문제가 아니라 **실행에 사용된 골든셋 버전이 수정본으로 교체되지 않은 데이터 문제**다.

골든셋 수정은 팀 승인 후 `review.status`와 버전·해시를 갱신하고, 동일한 저장 답변을 다시 채점해 반영한다.

## 6. 현재 확인된 한계

- v3.0.1은 의미 기반 LLM Judge가 아니라 결정론적 어휘 보조 채점기다.
- 형태소가 같지 않은 광범위한 동의 표현과 문장 의미는 완전히 판단하지 못한다.
- 근거를 포함한 올바른 기권을 `partial_answer`로 오분류할 수 있다.
- Golden Set v3의 검수 상태와 실행 파일 버전이 일치하지 않으면 점수가 왜곡될 수 있다.
- 서로 다른 실행의 답변과 원인 진단을 섞으면 채점 비결정성처럼 보일 수 있다.

## 7. 최종 판단

- v3.0.0은 과대 채점 때문에 사용하지 않는다.
- v3.0.1을 현재 결정론적 어휘 기반 채점기로 사용하되 G22 유형의 기권 판정은 보완한다.
- B15 정답 15개는 팀 승인 후 골든셋에 반영하고 재채점한다.
- `lexical_fact_score`는 의미 정확도를 보장하는 최종 종합점수가 아니라 보조지표다.
- 의미 정확도와 근거 충실도는 향후 사람 검수 또는 별도의 LLM Judge 평가로 보완한다.
