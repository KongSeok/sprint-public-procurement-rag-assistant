# 여러 사업 비교에서 근거 누락을 막는 장치

작성일: 2026년 9월 4일
대상 작업: `EH2.4 compare doc×field coverage`
대상 커밋: `e1ae064da1de35eca29547c568e520094d7eb57a`

## 1. 한눈에 보는 결과

EH2.4에서는 여러 사업을 비교할 때 일부 문서나 일부 비교 항목이 빠진 채 답변이 완성되는 문제를 막았다.
비교 대상을 문서와 항목의 조합으로 나누고, 각 조합마다 독립적으로 근거가 있는지 확인하는 구조다.

예를 들어 A사업과 B사업의 예산, 마감일, 필수 인력을 비교한다면 확인할 대상은 2개가 아니라 6개다.

| 비교 대상 | 예산 | 마감일 | 필수 인력 |
| --- | --- | --- | --- |
| A사업 | A×예산 | A×마감일 | A×필수 인력 |
| B사업 | B×예산 | B×마감일 | B×필수 인력 |

이 6개 칸을 모두 추적해야 두 사업을 빠짐없이 비교했다고 판단할 수 있다. 기존의 일반적인 Top-k 검색은
한 문서의 결과가 상위권을 차지하면 다른 문서의 근거가 빠질 수 있지만, EH2.4는 문서별·항목별 검색 범위를
따로 묶어 이 문제를 줄였다.

## 2. 이번에 구현한 것

```text
비교 질문
  → 비교할 문서와 항목 확정
  → 문서 수 × 항목 수의 전체 확인표 생성
  → 각 칸을 해당 문서 안에서만 검색
  → 검색 결과와 검증 상태를 영수증 형태로 기록
  → 문서별·항목별 근거 충족 여부 재계산
  → 모든 칸이 확인된 경우에만 정상 완료 허용
```

### 전체 비교표 생성

확정된 문서와 비교 항목의 모든 조합을 만든다. 일부 조합만 만든 부분 비교표는 허용하지 않는다.
비교 대상이 2건보다 적거나 문서가 명확하게 정해지지 않으면 임의로 대상을 골라 실행하지 않는다.

### 문서별 검색 범위 고정

각 칸은 하나의 문서 안에서만 검색한다. A사업의 예산을 찾는 검색 결과에 B사업의 문서가 섞이지 않도록
검색 범위를 고정하고, 실행에 사용한 문서·질의·예산·검색기 정보를 함께 기록한다.

### 비교 항목 오인 방지

사업명에 들어 있는 단어를 비교 항목으로 잘못 읽지 않도록 사업명과 별칭 구간을 먼저 제외한다.
`비교하지 말고`, `제외`, `빼고`처럼 사용자가 제외한 항목도 비교 축으로 선택하지 않는다. 지원하지 않는
항목이 섞여 있으면 아는 항목만 몰래 실행하지 않고 미해결 상태로 남긴다.

### 성급한 완료 판정 차단

관련 있어 보이는 청크를 찾았다는 사실만으로 값이 확인됐다고 처리하지 않는다. 값과 근거를 확인하는
정식 검증 영수증이 없으면 해당 칸은 후보 상태로 남는다. 검색 결과가 비어 있어도 곧바로 "정보 없음"으로
확정하지 않고 임시 미확인 상태로 둔다.

### 비교 범위 재검산

전체 칸의 상태와 문서별 충족 상태를 원자료에서 다시 계산한다. 상단의 합계 숫자만 고치거나 내부 칸을
바꾼 객체는 유효한 비교 결과로 인정하지 않는다.

## 4. 왜 중요한가

입찰 문서 비교 질문은 답변 문장이 자연스러운지만 봐서는 품질을 판단하기 어렵다. A사업의 예산과
B사업의 마감일만 찾고도 두 사업을 비교한 것처럼 답할 수 있기 때문이다. EH2.4는 비교해야 할 칸의
전체 개수와 확인된 칸을 드러내므로 다음 항목을 평가할 수 있게 한다.

- 비교 대상 문서가 모두 검색됐는가
- 요청한 비교 항목이 문서마다 빠짐없이 확인됐는가
- 찾지 못한 값과 아직 검증하지 않은 값이 구분되는가
- 일부 근거만으로 완전한 비교라고 답하지 않는가

따라서 골든셋에서는 정답 문장뿐 아니라 `필요한 문서×항목 중 몇 칸을 근거로 채웠는가`를 함께
측정할 수 있다. 여러 사업의 금액, 일정, 인력 조건을 비교하는 서비스 기능에 직접 필요한 기반이다.

## 5. 정확한 한계

EH2.4만으로 사용자에게 최종 비교표를 보여주는 기능이 완성된 것은 아니다.

- 관련 청크를 찾은 단계와 실제 값이 검증된 단계를 구분하지만, 최종 값 검증은 후속 실행기가 맡는다.
- 모든 검색 경로를 실행한 뒤 정보 부재를 확정하는 절차는 EH2.6의 책임이다.
- 상태 전이, 반복 검색, 최종 답변 생성, Streamlit 화면 연결은 별도 후속 작업이다.
- 같은 골든셋으로 기존 베이스라인과 성능을 비교하지 않았으므로 검색 성능이 향상됐다고 주장할 수 없다.

현재 정확한 표현은 "다중 문서 비교의 근거 누락과 조기 완료를 막는 실행 기반을 구현했다"이다.

## 6. 발표용 요약

> 여러 사업을 비교할 때 한 문서의 검색 결과만 많이 나와도 답변이 완성되는 문제를 막았습니다.
> 비교 대상을 문서와 항목의 조합으로 나누고, 각 조합을 해당 문서 안에서 따로 검색하도록 만들었습니다.
> 관련 청크를 찾은 것과 실제 값을 확인한 것도 구분하며, 모든 칸이 검증되기 전에는 완전한 비교로
> 종료하지 않습니다. 집중 테스트 107개와 당시 전체 테스트 987개를 통과했습니다. 다음 단계에서는
> 이 구조를 최종 답변 생성과 골든셋 A/B 평가에 연결합니다.
