## VM과 실제 실행에서 확인한 내용

### 제한 실행은 전체 재평가로 이어지지 못했다

15:37 신뢰 VM에서 고정한 12개를 실행했다. RAG 문항은 답변 4개와 오류 8개였고, 파서 회귀 2개는 통과했다. 26회 대화에 275.256초가 걸렸으며 자동 재시도는 없었다. 입력 예산을 맞춘 것과 생성 출력이 정상인 것은 별개라서 전체 131개 재평가는 보류했다.

별도 CPU 환경에서는 XGrammar preview matcher 합성 입력 180개를 확인했다. 정상 JSON escape는 허용하고 빈값·공백·중복 key·길이 초과는 거절하는 동작을 재현했다. 인용 배열의 동일 ID는 schema가 허용하고 strict 검사가 거절하는 차이가 남아 있어, Linux/vLLM이나 공유 VM에 적용하지 않았다.

실패 후보를 점검한 뒤 제품 런타임은 `candidate002 c232`로 되돌렸다. 복원 후 집중 37/37, 기존 기록 129/129, 원래 상태 오류 52/52를 확인했으며 후보 30개 중 4개 실패도 성공으로 바꾸지 않았다. QUICKQA 통합 1회는 120.061초에서 lexical 단계가 끝나지 않았고 생성 호출은 관측되지 않았다.

## 9월 9일 HOTLINE.2 작업

새 로컬 serving 작업은 고정 hotline 경로를 쓰도록 진입점을 정리했다. 기존 Controller 소스와 이력은 보존하고 active entrypoint에서만 제외했다.

| 구분 | 확인 결과 | 해석 |
| --- | --- | --- |
| 구현 | `midprojectrag.hotline` 고정 파이프라인, hotline 전용 CLI, 기존 launcher 호환 shim | Controller와 hotline을 명시적으로 분리한 구현 |
| 집중 검사 | 30개 통과 | 새 경로의 단위·계약 검사 |
| 공용 회귀 | 64개 통과 | retrieval·scope·public parent 관련 회귀 |
| 합계 | 94개 통과, skip 없음 | 집중·공용 회귀 결과이며 제품 전체 회귀는 아님 |
| synthetic tracing | Controller 실행·decision 호출 0회, dense·lexical·generation 각 1회 | hotline 경로가 Controller를 거치지 않는지 확인 |
| 실제 품질 | 실제 모델·UI·전체 회귀·독립 검수 미실행 | 정답률·속도 개선·기본 프로필 승격으로 해석하지 않음 |

실행기와 worker timeout 처리는 유지했지만, 패키지 재설치와 실제 모델·API·GPU·VM 실행은 하지 않았다. 저장소 안전 검사는 기존 협업 JSON의 패턴 때문에 실패했고 이번 HOTLINE 파일에서 새로 검출된 것은 없었다. 이 때문에 구현을 Git에 커밋하거나 푸시하지 않았다.
