## VM에서 실제로 확인한 내용

### 1. 제한된 12개 실행은 여전히 실패했다

15:37 신뢰 VM에서 코드 staging과 처리를 승인받아 고정한 12개를 실행했다. RAG 문항은 답변 4개와 오류 8개였고, 파서 회귀 2개는 통과했다. 26회 대화에 275.256초가 걸렸으며 자동 재시도는 없었다.

이 실행은 입력 문맥을 줄이는 수리가 적용되는지 확인하기 위한 것이었다. 입력 준비가 통과한 것과 생성 출력이 정상인 것은 분리해서 봐야 한다. 현재 결과로는 전체 131개를 다시 돌리거나 새 점수를 계산할 근거가 없다.

### 2. 구조화 출력 검사기를 별도 CPU 환경에서 진단했다

설치한 XGrammar 0.2.3 계열의 preview matcher를 제품과 분리된 CPU 환경에서 확인했다. 합성 입력 180개를 검사한 결과 정상적인 JSON escape는 허용했고, 빈값·공백·중복 key·길이 초과는 거절했다. 독립 재실행 결과도 같았다.

다만 인용 배열의 동일 ID 중복은 schema가 허용하고 strict 검사가 거절하는 차이가 남아 있다. 이 차이를 정리하지 않은 채 공유 VM이나 vLLM에 적용하지 않는다. 이번 진단에서는 제품, VM, 모델을 바꾸지 않았고 새 생성도 하지 않았다.

### 3. 실패 후보를 안전하게 되돌리고 추가 실행을 멈췄다

검사한 후보 중 정상 escape·빈값·중복·길이 조건을 모두 만족하는 후보가 없어 미완성 변경을 비공개 백업하고 `candidate002 c232`로 복원했다. 복원 후 집중 검사 37/37, 과거 기록 129/129, 원래 상태 오류 52/52를 다시 확인했다. 후보 검사 30개 중 4개 실패도 별도로 보존했으며 성공으로 바꾸어 세지 않았다.

이후 QUICKQA 통합을 1회 제한 시간으로 확인했다. 실행은 120.061초에서 끝났고 lexical 단계가 끝나지 않았으며, 생성 호출은 관측되지 않았다. 따라서 Controller 통합이 끝났거나 실제 답변 품질이 개선됐다고 판단하지 않는다.
